## 13:39 — Fixed completed Slack turns stalling before reply delivery

- **Observed failure:** A Slack DM reached the isolated dev `Chat Smoke Test`
  Agent Chat and produced one completed Codex turn with one final assistant
  message, but Slack history contained only the inbound user messages and no bot
  reply. The bridge emitted no Slack-post error and held only its T3 and Socket
  Mode connections, proving it was still waiting before the outbound API call.
- **Root cause:** `ThreadTracker` correlated Slack messages to provider turns by
  waiting for `thread.turn-start-requested`, while the production thread-detail
  WebSocket intentionally excludes that event. Existing tests injected the
  unavailable event, so they did not reproduce the real stream. The bridge
  therefore waited for a turn ID indefinitely even after the turn and final
  assistant message completed.
- **Fix:** Queue a newly observed user `thread.message-sent` event only when its
  durable `externalSource` is `slack`, then correlate it with the next running
  provider session. Updated both direct and queued-turn tests to use the actual
  detail-stream event sequence.
- **Verification:** Six focused tests passed across `ThreadTracker` and the T3
  thread client, the bridge typecheck passed, and `git diff --check` passed. The
  fixed foreground bridge reconnected to Slack and the isolated dev Agent Chat
  without errors. A fresh manual Slack DM remains the final live outcome test.
- **Boundary:** No Slack message was sent by the maintainer, no LaunchAgent was
  installed, and no push, tag, deployment or release was created.
